RFC 002: Split the QuantumFloat class into QuantumInt and QuantumFloat

  • Feature Name: QuantumInt Class
  • Start Date: 2026-11-10
  • RFC PR: (leave empty until the pull request is opened)
  • Qrisp Issue: (link the tracking issue, if one exists)

Summary

QuantumFloat currently serves double duty: it is the integer type when exponent=0 and a fixed-point type otherwise. There is no dedicated integer class. QuantumModulus inherits from QuantumFloat directly, which forces it to suppress float-specific methods that would produce incorrect results on modular integers.

This RFC introduces QuantumInt as a subclass of QuantumFloat with exponent fixed to 0, and re-parents QuantumModulus under QuantumInt. The type hierarchy becomes:

    QuantumVariable → QuantumFloat → QuantumInt → QuantumModulus

This decouples integer arithmetic from floating-point arithmetic, gives modular types a clean base that doesn't carry float-only operations, and lets adders and other integer infrastructure target QuantumInt without pulling in exponent alignment or precision concerns that only matter for floats.
